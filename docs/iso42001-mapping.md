## Executive Overview

ISO/IEC 42001:2023 is the international standard for an Artificial Intelligence Management System (AIMS). When organizations deploy autonomous agents capable of non-deterministic decision-making and automated tool invocation, standard IT controls (ISO 27001) fail to cover model reasoning drift, prompt injection, and ambient service privilege escalation.

The **Agentic Zero Trust Architecture (AZTA)** provides an out-of-band enforcement layer that maps directly to ISO 42001 Annex A controls, enabling organizations to achieve certified compliance without relying on probabilistic model alignment.

## Detailed Control Enforcement Protocols

### 1. Control A.8.3: Operational Controls & Interface Validation
* **Requirement:** Ensure all inputs and outputs across AI system boundaries conform to strict system boundaries and prevent malicious input manipulation.
* **AZTA Implementation:**
  * Model reasoning engines output tool call proposals in structured JSON.
  * The AZTA Gateway intercepts proposals and validates input parameters against pre-compiled JSON Schemas prior to dispatching to MCP tool endpoints.
  * String parameters destined for SQL drivers or CLI utilities are evaluated using static analysis Rego rules (`policies/common/security_guards.rego`) to block parameter injection (e.g., `; DROP TABLE`, `&& rm -rf`).

### 2. Control A.9.2: Access Control for Non-Human Identities
* **Requirement:** Manage access permissions for automated AI components, preventing elevated ambient privileges.
* **AZTA Implementation:**
  * Agents execute tools under **Delegated User Identity** via RFC 8693 Token Exchange.
  * When `AGT-001` calls an enterprise API on behalf of User `usr_123`, the gateway trades the user's bearer token for a 15-minute ephemeral token scoped *strictly* to `usr_123`'s RBAC scope.
  * Eliminates shared service accounts and static administrative keys.

### 3. Control A.10.2: Log Protection & Non-Repudiation
* **Requirement:** Ensure operational logs generated by AI systems are protected against tampering, alteration, or deletion.
* **AZTA Implementation:**
  * Every transaction generates a canonical audit event conforming to `schema/azta_audit_record.v1.json`.
  * The gateway generates an `integrity_signature` using HMAC-SHA256 with a KMS-stored secret key.
  * Logs are written directly to Write-Once-Read-Many (WORM) storage (e.g., S3 Object Lock in COMPLIANCE mode) with a mandatory 365-day retention period.

## Audit Verification Checklist for ISO 42001 Lead Auditors

- [ ] Verify zero static API keys/PATs exist in environment variables, application code, or system prompt strings.
- [ ] Verify that 100% of outbound tool calls traverse an out-of-band OPA policy proxy.
- [ ] Inspect OPA test execution output (`opa test policies/ -v`) to confirm 100% policy branch coverage.
- [ ] Confirm S3 Object Lock configuration is set to `COMPLIANCE` mode with `force_destroy = false`.
- [ ] Verify that invalid tool parameter proposals return an HTTP 403 Forbidden without reaching the target tool backend.
